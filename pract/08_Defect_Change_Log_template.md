> Цей файл поєднує Defect Log (що знайдено) і Change Log (як виправлено). Для кожного запису: клас, джерело, правка, доказ, повторна перевірка.

## Класифікація

- **DEF** — невідповідність вимозі зі специфікації або погодженому brief. Виправлення обов'язкове.
- **UX** — рекомендація покращення, не формальний дефект. Може бути відхилена.
- **Q** — неузгоджене питання, потребує рішення людини.

**Severity (для DEF):**
- **Critical** — прав або переходи порушено; робота не готова до здавання.
- **Major** — помилка, що впливає на перевірку AC.
- **Minor** — локальна помилка, яка не ставить під сумнів відповідність.
- **Trivial** — косметика.

## Етапи, на яких виявлено

- G1 Source check — при перевірці Input Pack на повноту AC.
- G4 Plan Review — рецензент перевірив план перед Figma.
- Ручний огляд після F1 — студент перевірив макет без AI.
- F2 Agent correction — Agent отримав список дефектів і зробив правки.
- Ручний огляд після F2 — чи фактично виправлено.
- G6 Final Review — AI + студент перевірили докази.
- Мінітест з одногрупником — виявлено UX проблеми в проходженні.

## Правила ведення

1. Для кожного знайденого дефекту вкажіть джерело (не «погано виглядає», а «суперечить AC-07.4»).
2. Не позначайте FIXED, якщо не маєте видимого доказу зміни у фактичному фреймі.
3. Якщо дефект виправив Figma Agent — збережіть запит у `09_AI_Interaction_Log.md` і посилання на нього тут.
4. REJECTED UX записи не приховуйте — це робить журнал повним.
5. При новій версії макета повторно пройдіть по журналу: що ще раз зламалося.
